5 systems (the business team's 9 Nov mapping, docs/data-model/DATA_MODEL.md):
BUSS - Holds customer sales orders
Oracle - Holds the item master and the planning forecast
MIPS - Plans production: the demand left after allocated stock, and the work order for the shortfall
ODI - Joins each order line and forecast to its work order and MIPS batches
WMS - Holds all on-hand stock: available and allocated

These systems frequently show different quantities for the same product. Today people compare screens by hand.
Slow process, requires domain expertise and human intervention.

---------------------------------------------------------------

When 3 systems out of sync, problems:
- Plant makes more of what prod already exists (over prod).
- Surplus prod stays on one sales day and not used on next sales day
- Warehouse ships stock that MIPS doesn't know of
- Oracle / ODI has no idea of shipments, finance cannot close periods correctly 

---------------------------------------------------------------

Reconciliation Agent, Solution:
Compares data from the five systems for each product (SKU) and each sales day. 
Steps:
1. Calculate one current position for each SKU
2. 13 fixed rules, one for each step of the demand-to-delivery flow
3. Flags each mismatch, flag tells you the problem, system that is wrong or out of sync and the correction. 
4. Puts the flags in sequence. Flag with largest retail value at risk is first priority
5. Records each planner decision, uses decisions to change the sequence of subsequent flags

---------------------------------------------------------------

Main principles
- Rules calculate, AI explains 
Rules calculate each quantity, AI explains the 
- Agent adds all demand (every BUSS order line and the Oracle forecast) before it applies stock. Prevents over-production.
- Agent gives corrections, not just differences. For example: "Cut work order WO-UBD-20260912-002 to 3,700: WMS already has 1,140 available."
- Business person makes the final decision, phase 1 only proposes changes with accept or reject options.

---------------------------------------------------------------

Problem Identification:
Step 1: Input data
Agent reads one workbook (or the live event feed) with one sheet per source: ITEM Master, Sales Orders (BUSS), Oracle Planning & Forecast, ODI Batch Data Entry Mapping, WMS and MIPS.

Step 2: Reconciled Position
Agent uses the business team's equation:
Total demand   = Sales orders (BUSS, all lines) + Forecast (Oracle)
Demand left    = Total demand - Allocated stock (WMS)       -> MIPS Forecast / Order Quantity
Shortfall      = Demand left - Available stock (WMS)        -> MIPS Work Order Quantity
Check          = Work order + Available + Allocated = Total demand
- Example, 76108: (14,339 + 41,769) - 473 - 7,000 = 48,635.
- When available stock covers the demand left, the shortfall is 0 and no work order is needed. The surplus stays in WMS (all on-hand stock is kept in WMS only).
- An item with only a forecast is planning, not yet scheduled: it gets no position.

Step 3: Rules
R01(H) - A BUSS order line or Oracle forecast is missing from the ODI mapping.
R02(M) - The ODI quantity differs from the BUSS order or Oracle forecast.
R03(M) - ODI maps an order or forecast that no longer exists (cancelled).
R04(M) - The MIPS Forecast / Order Quantity is not the demand less allocated stock.
R05(H) - The MIPS work order is not sized to the shortfall (over- or under-production).
R06(H) - A shortfall has no MIPS work order.
R07(M) - The ODI work order (number or quantity) differs from MIPS.
R08(M) - A demand line has neither allocated stock nor a work order.
R09(M) - The allocated stock differs between WMS and ODI.
R10(M) - WMS on hand is not available plus allocated.
R11(L) - The batches mixed differ from the MIPS schedule.
R12(H) - Finished goods were wrapped after the requested ship date.
R13(L) - Item or BUSS codes differ between the item master, BUSS, MIPS and ODI.

Quantity rules change severity with size: High at 1,000 units or more, otherwise Medium.

NOTE: The workbook also describes raw-material checks (if FG is not available, check components, then inbound RM). They need a bill of materials and RM stock, which the workbook does not have yet.

Step 4: Priority
The agent puts the flags in sequence by priority. The flag with the highest priority is first.
Priority = (Retail value at risk + base value) × Severity weight × Rule confidence

Severity| Weight
--------|--------
High	| 3
Medium	| 2
Low	    | 1

- The retail value at risk is the number of units multiplied by the retail price of the SKU.
- The base value makes sure that flags with no dollar value (for example, R12) also get a position in the sequence.
- Rule confidence starts at 1.0.

Step 5: Explanations
Each flag has an explanation text. The explanation can come from two sources:

- Rule text. The rule writes the text. This text is always available.
- AI explanation. An AI model (Gemini 2.5 Pro on OCI Generative AI) writes the text. It also gives a root cause and an owner, the chain of events (one system for each step), the business impact, the record that confirms the cause, and the linked flags.

The label above each explanation tells you the source. If the AI model is not available, the agent uses the rule text. The agent continues to operate correctly without the AI model.

System accountability
Each flag also shows which system caused the problem. The rules calculate this, not the AI. Thus, it is always available, and the AI cannot change it.
- Impact: over-production, under-production, short shipment, overstated inventory, traceability gap or data integrity.
- Started in: the system where the error started (BUSS, Oracle, MIPS, ODI or WMS), or Integration when the connection between two systems failed.
- Failure: how the system went wrong (for example, planning change, stale data, missing transaction).
- Attribution: Certain, Likely or Undetermined.
- One line for each system (MIPS, ODI, WMS, and BUSS or Oracle if involved) with its role: Misfired, Affected, Reference, Conflicting, To check or Not involved.

AI checks and audit
- The agent compares each number in the AI text with the numbers of the rules. If the AI writes a number that the rules did not calculate, the flag shows "not in the engine's data". Do not use that number.
- Each AI explanation, briefing and assistant answer shows an Audit number. The audit log (ai_audit.jsonl) keeps the data that the AI received, the answer of the AI and the result of the checks.
- If the agent cannot write the audit log, it does not show the AI text. It shows the rule text.

---------------------------------------------------------------

Procedures
1 - Sign in
- Open the worklist address in a web browser. Your IT team gives you this address (for example, http://localhost:8001/).
- On the "Who's on shift?" screen, type your name in the Name box.
- Select your role: Planner, Supervisor or Manager.
- Push Open the worklist.
- Result: The Exception worklist opens.

NOTE: The agent puts your name on each claim, acknowledgment and decision. Use your real name. In production, the plant sign-in system (OCI IAM Identity Domains) will replace this screen.

2 - Read the shift briefing
- Find the Shift briefing area at the top of the queue.
- Read the first sentence.
- To see all of the briefing, push Read briefing.
- Read the briefing text and the Top actions list.
- To open the SKU of an action, push the SKU number at the start of that action.
- Read Where today's flags started. It shows the flags, High flags, units and dollars for each system that caused them.
- When you complete the briefing, push Mark read.
- Result: The briefing closes. It stays closed on this computer until the agent loads new data.

To read the briefing again, push Read again.

3 - Find a row
To show the rows for one sales day:
- Push the tile of that sales day.

To show all sales days:
- Push All open days.

To show a specified group of rows:

- Push one of the view tabs:
	- Open: rows with one or more open flags.
	- Needs acknowledgment: rows with a High flag that nobody acknowledged.
	- Claimed by me: rows that you claimed.
	- Decided: rows where all flags have a decision.

To find a SKU or an item:
- Push the / key, or push the search box.
- Type the SKU number or a part of the item name (for example, 76108 or hamburger).
Result: The queue shows only the rows that match.

To move in the queue with the keyboard:
1. Push j to go to the next row.
2. Push k to go to the previous row.
3. Push Enter to open the row.
4. Push Esc to close the detail.

4 - Examine a row
- Push the row in the queue.
Result: The detail area shows the row.

- Read the Reconciled position equation:
	- Sales orders (BUSS) plus forecast (Oracle) equals total demand.
	- Minus allocated stock (WMS) equals the demand left. The line shows whether MIPS plans the same quantity.
	- Minus available stock (WMS) equals the shortfall. The line shows whether the MIPS work order is the same quantity.
	- The check: work order plus available plus allocated against demand.

- Read the bar. It shows allocated and available stock (grey), the work order (black) and the demand mark on one scale. Over-production shows after the demand mark. A shortage shows before it.
- Read the systems table. It shows the BUSS, Oracle, ODI, WMS and MIPS quantities on the same scale.
- Read each flag in the Flags area. Each flag shows:
	- The severity, the rule code and the title.
	- The units and the dollar value.
	- The explanation (rule text or AI explanation).
	- The owner and the root cause (or scenario).
	- The system accountability: the impact, the system where the problem started, and the role of each system. Refer to Step 5.
	- For an AI explanation: How it happened, Confirm with, the check of the numbers and the Audit number.
	- The evidence values.
- To see the original records, push Source records.
Result: The screen shows the BUSS order lines, the Oracle forecast, the ODI mapping rows, the WMS stock and the MIPS work orders for this SKU.

5 - Claim a row
Claim a row to tell other supervisors that you work on it.
 - Open the row.
 - Push Claim.
Result: The detail shows "Claimed by you". The queue shows your initials on the row. The row shows in your Claimed by me view.

To release the claim:
 - Open the row.
 - Push Release.
NOTE: If a different person claimed the row, the detail shows the name of that person. You can still make a decision. The agent then records your name, not the name of the other person.

6 - Acknowledge a High flag
You must acknowledge each High flag in 15 minutes.
- Push the Needs acknowledgment tab.
- Open the row.
- Find the flag that shows "acknowledge by HH:MM".
- Push Acknowledge.
Result: The flag shows "Acknowledged by (your name) at (time)".

CAUTION: If nobody acknowledges a High flag in 15 minutes, the flag becomes overdue. The plan sends overdue flags to the plant productivity manager.

7 - Accept or reject a flag
- Open the row.
- Read the flag, the evidence and the source records.
- Make sure that you have the current data. Refer to Section 6.2.
- If necessary, type a note in the Note for the next shift box. Write what you examined or changed.
- Do one of these steps:
	- If the flag is correct, push Accept.
	- If the flag is not correct, push Reject.
Result for Accept: The flag shows "Accepted". The status is "awaiting correction in the source system".

Result for Reject: The flag shows "Rejected". The agent decreases the confidence of the rule. On the next run, the agent does not show this flag again if the quantity stays the same.

- If you accepted the flag, make the correction in the source system. The text below Accept tells you the system (for example, MIPS).
CAUTION: In Phase 1, Accept does not change MIPS, WMS or Oracle. You must make the correction in the source system manually. If you do not, the problem stays.

To change a decision:
	- Open the row.
	- Push Change decision below the flag.
	- Push Reject instead or Accept instead.

8 - Surplus stock
When WMS has more stock available than the demand left, no work order is needed and the surplus stays in WMS (all on-hand stock is kept in WMS only). Rule R05 then asks to cancel or cut the work order. No surplus is carried to another sales day.

9 - Ask the assistant a question
- Push Ask in the top strip.
- Type your question in the box. Use 500 characters or less. For example: Why is the 950513 work order bigger than the shortfall?
- Push Ask.
Result: The answer shows below the box. The answer gives links to the related rows.
- To open a row from the answer, push the link.
- To close the assistant, push the X button or push Esc.

NOTE: If the AI model is connected, the AI writes the answer. It gets all numbers from the agent data. The answer shows an Audit number and a check of its numbers against the data that the assistant looked up. If the AI model is not connected, the assistant shows the agent data for the SKU numbers or the item names in your question.

10 - Sign out
Push the sign-out button next to your name in the top strip.
Result: The sign-in screen opens.
